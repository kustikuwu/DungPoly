# DungPoly
## О проекте
### Основная идея
DungPoly — компьютерная версия экономической настольной игры для 2–6 игроков.

Цель игры — рационально используя стартовый капитал, добиться банкротства других игроков.

Подробнее узнать об игре, а также ознакомиться с правилами, вы можете [здесь](https://www.keft.ru/help/mnp/rules).

### Проект
В игре можно покупать и продавать недвижимость, строить дома и гостиницы, участвовать в торгах и обмениваться собственностью.

Приложение написано с использованием **SFML**.

Реализованы: 
* Локальная и сетевая игра
* Выбор количества игроков (от 2 до 6)
* Покупка и продажа собственности, строительство, обмен и аукционы

## Установка
Поддерживаемые операционные системы: **Linux** и **macOS**.

### Необходимые библиотеки
* SFML 2.5.1
  * Linux
  ```shell script
  $ sudo apt-get install libsfml-dev
  ```
  * macOS
  ```shell script
  brew install sfml
  ```
* sockpp (подключена как Git-подмодуль)
  ```shell script
  $ git submodule update --init --recursive
  ```
* [Protocol Buffers 3.11.4](https://github.com/protocolbuffers/protobuf)
  ```shell script
  $ cd protobuf
  $ ./configure
  $ make
  $ sudo make install
  $ sudo ldconfig
  ```

### Сборка
```shell script
$ git clone --recurse-submodules https://github.com/kustikuwu/DungPoly.git
$ cd DungPoly
$ mkdir build
$ cd build
$ cmake ..
$ make
```

### Запуск

Из директории `build` запустите приложение:

 ```shell script
      $ ./DungPoly
  ```

### Управление

* Левая кнопка мыши — выбрать действие или клетку поля.
* Правая кнопка мыши — показать сведения о клетке.
* Во время торгов и подключения по сети вводите запрошенные данные с клавиатуры.
* Чтобы начать локальную игру, добавьте от двух до шести игроков и нажмите «Начать игру».
* Для сетевой игры добавьте одного игрока и нажмите «Подключиться».
 
Во время игры слева находится панель действий. Подсвечиваются действия, доступные текущему игроку. Наведите указатель на кнопку, чтобы увидеть подсказку. Сведения о клетке отображаются в правом нижнем углу.

## Веб-лобби и браузерные партии

Веб-модуль позволяет зарегистрироваться, войти, создать лобби на 2–6 игроков и присоединиться к партии из браузера. Каждая комната открывается на отдельной странице с компоновкой и оформлением оригинального интерфейса SFML: доской по периметру, центральной панелью, карточкой поля и панелью действий. Для кнопок, фишек и шрифта используются файлы из `resources/`; это браузерный интерфейс, а не запуск Windows `.exe`. Веб-сервер запускает отдельный процесс `DungPolyWebEngine` для каждой партии, поэтому правила и состояние игры по-прежнему обрабатывает существующее C++-ядро. Для игры через интернет нужен сервер с собранным движком, но отдельный компьютер с графической сессией не требуется.

Требуются CMake и Node.js 20 или новее. Сначала соберите игровой движок из корня проекта:

```shell
cmake -S . -B build
cmake --build build --config Release --target DungPolyWebEngine
```

Затем установите зависимости и запустите веб-сервер:

```shell
cd web
npm install
npm start
```

Откройте `http://127.0.0.1:3000`. В лобби должно быть не менее двух игроков; начать партию может его владелец. Игровое поле и действия синхронизируются между браузерами через WebSocket. Игрок может сдаться из меню действий; партия завершается автоматически, когда остаётся один игрок. Регистрация и вход доступны только по подтверждённому одноразовым кодом адресу электронной почты. Перенос и вход в старые аккаунты отключены. Пользователи, комнаты, хеши кодов и хеши случайных сессионных токенов сохраняются в `web/data/store.json`; файл с данными исключён из Git.

Для отправки кодов задайте переменные окружения `GMAIL_USER`, `GMAIL_APP_PASSWORD` и `DUNGPOLY_OTP_SECRET` (длинный случайный секрет для HMAC-хеширования кодов). Для Gmail включите двухэтапную проверку и создайте [16-символьный пароль приложения](https://support.google.com/accounts/answer/185833?hl=ru); обычный пароль Google использовать нельзя. Google может не разрешить пароли приложений для некоторых типов аккаунтов. Не сохраняйте секреты в репозитории и не отправляйте их в чат. Новые отправители иногда попадают в спам: отметьте письмо как «Не спам» и добавьте адрес отправителя в контакты. Для production-рассылки используйте домен с настроенными SPF, DKIM и DMARC у почтового провайдера. Код действует 10 минут, после пяти неверных попыток его можно запросить заново. Имена профилей и комнат проверяются по английскому и русскому словарям с нормализацией распространённых подмен символов; чат-модерация не используется.

Для Cloudflare Pages в настройках проекта укажите каталог сборки `web/public`; конфигурация Pages Functions находится в `web/functions`. Добавьте переменную `DUNGPOLY_BACKEND_ORIGIN` с HTTPS-origin игрового сервера. Pages проксирует `/api/*` и `/lobby/*` на него, сохраняя same-origin cookie и WebSocket. На игровом сервере задайте `DUNGPOLY_PUBLIC_ORIGIN=https://dungpoly.pages.dev`, а также секреты отправки писем.

Для временного теста с домашнего компьютера можно запустить `cloudflared tunnel --url http://127.0.0.1:3000` и указать выданный `trycloudflare.com` адрес как `DUNGPOLY_BACKEND_ORIGIN`. Компьютер и оба процесса должны оставаться включёнными; Quick Tunnel имеет временный меняющийся адрес и не гарантирует доступность, поэтому это не постоянный production-хостинг. При смене адреса его нужно обновить в настройках Pages. Локальный JSON-файл и встроенный лимитер рассчитаны только на один процесс и не заменяют промышленную БД и общий rate-limit store при горизонтальном масштабировании.

Проверки веб-модуля запускаются командой `npm test` из каталога `web`.
